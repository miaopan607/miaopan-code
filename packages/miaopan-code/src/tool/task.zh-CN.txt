启动一个新代理，自主处理复杂的多步骤任务。

使用 Task 工具时，必须指定 subagent_type 参数，以选择要使用的代理类型。

只要已创建子代理会话，每个任务结果都会提供 task_id，包括失败结果。子代理被中断或以错误结束后，使用相同的 subagent_type 和 task_id 可原地继续失败的回合。是否继续由主线程根据上下文决定；Task 工具不会自动重试。

不要在以下情况下使用 Task 工具：
- 如果要读取特定文件路径，请使用 Read 或 Glob 工具而不是 Task 工具，以便更快找到匹配项
- 如果要搜索 "class Foo" 之类的特定类定义，请改用 Grep 工具，以便更快找到匹配项
- 如果要搜索某个特定文件或一组 2–3 个文件中的代码，请使用 Read 工具而不是 Task 工具，以便更快找到匹配项
- 如果没有适合该任务的可用代理，请直接使用其他工具


使用说明：
1. 尽可能并发启动多个代理，以最大限度提高性能；为此，请在一条消息中使用多个工具调用
2. 将工作委派给代理后，不要自行重复该工作。继续处理不重叠的任务，或等待结果。对于后台任务，结果准备好后你会自动收到通知。
3. 代理完成后，会向你返回一条消息。代理返回的结果对用户不可见。要向用户展示结果，你应向用户发送一条文本消息，简要总结结果。输出中包含一个 task_id，之后可以复用它来继续同一子代理会话。
4. 除非提供 task_id 以恢复同一子代理会话（该会话会延续之前的消息和工具输出），否则每次代理调用都从全新上下文开始。全新启动时，prompt 应包含高度详细的任务说明，供代理自主执行；你还应明确指定代理在最后且唯一的一条消息中向你返回哪些信息。
5. 通常应信任代理的输出
6. 明确告诉代理你期望它编写代码，还是只做研究（搜索、读取文件、网页抓取等），因为它不知道用户的意图。尽可能告诉它如何验证工作（例如相关测试命令）。
7. 如果代理描述提到应主动使用它，你就应尽最大努力在无需用户提出要求的情况下使用它。请自行判断。
