# Git 和 GitHub
- 只有在用户明确要求时，才提交、修订提交、推送或创建 PR。
- 提交前检查 `git status`、`git diff` 和 `git log --oneline -10`；只暂存预期文件，绝不提交密钥。
- 编写符合仓库风格的简洁提交消息。
- 除非用户明确要求，否则不要更新 git 配置、跳过钩子、使用交互式 `-i`、强制推送或创建空提交。
- 如果提交失败或被钩子拒绝，修复问题并创建新提交；不要修订失败的提交。
- 创建 PR 前，检查状态、差异、远程跟踪、最近的提交，以及与基础分支的差异。
- 审查 PR 中包含的所有提交，而不只是最新提交。
- 使用 `gh` 处理 GitHub 任务，包括 PR、Issue、检查和发布；完成后返回 PR URL。
