为当前编码会话创建并维护结构化任务列表。它用于跟踪进度、组织多步骤工作，并向用户展示状态。

## 何时使用
在以下情况下主动使用：
- 任务需要 3 个或更多不同的步骤或操作（而不是为单个概念步骤调用 3 次工具）
- 工作并非简单任务，且适合进行规划
- 用户提供了多个任务（编号或以逗号分隔），或明确要求任务列表
- 收到新指令——将其记录为 todo
- 开始任务时——工作前将其标记为 `in_progress`（一次只能有一个）
- 完成任务时——将其标记为 `completed`，并添加工作期间发现的所有后续事项

## 何时不使用
在以下情况下跳过：
- 工作是单个直接的任务（或少于 3 个简单步骤）
- 请求纯粹是信息咨询或对话
- 跟踪不会带来组织价值

## 状态
- `pending`——尚未开始
- `in_progress`——正在进行（一次必须恰好有一个）
- `completed`——已成功完成
- `cancelled`——不再需要

## 规则
- 实时更新状态；不要批量标记完成
- 只有在所需工作实际完成（包括所有必要验证）后才标记为 `completed`。绝不能仅根据意图标记。
- 只要还有工作，就保持恰好一个 `in_progress`
- 如果被阻塞或仅部分完成，保持 `in_progress`，并添加一个描述阻塞因素的后续 todo
- 原样保留用户提供的命令（flag、参数、顺序）
- 项目应具体且可执行；将大型工作拆分为较小步骤

## 示例

使用：
- "Add a dark mode toggle and run the tests" → 多步骤功能 + 明确验证
- "Rename getCwd -> getCurrentWorkingDirectory across the repo" → grep 发现 8 个文件中有 15 处
- "Implement registration, catalog, cart, checkout" → 多个复杂功能

跳过：
- "How do I print Hello World in Python?" → 信息咨询
- "Add a comment to calculateTotal" → 单次编辑
- "Run npm install and tell me what happened" → 一条命令

如果有疑问，就使用它。
