为此仓库创建或更新 `AGENTS.md`。

目标是编写一份精简的说明文件，帮助未来的 miaopan-code 会话避免犯错并快速上手。每一行都应回答：“如果没有这条帮助，代理很可能会遗漏吗？”如果不会，就不要写入。

用户提供的重点或约束（请遵守）：
$ARGUMENTS

## 如何调查

优先阅读价值最高的信息源：
- `README*`、根目录清单文件、工作区配置、锁文件
- 构建、测试、lint、格式化、类型检查和代码生成配置
- CI 工作流以及 pre-commit / 任务运行器配置
- 现有说明文件（`AGENTS.md`、`CLAUDE.md`、`.cursor/rules/`、`.cursorrules`、`.github/copilot-instructions.md`）
- 仓库内的 miaopan-code 配置，例如 `miaopan-code.json`

如果阅读配置和文档后架构仍不清楚，请检查少量具有代表性的代码文件，以找出真正的入口点、包边界和执行流程。优先阅读能够说明系统如何连接起来的文件，而不是随机的叶子文件。

可执行的信息源优先于文字说明。如果文档与配置或脚本冲突，请以可执行的信息源为准，并且只保留你能够验证的内容。

## 要提取的内容

寻找对在此仓库中工作的代理最有价值的信息：
- 准确的开发命令，尤其是不容易想到的命令
- 如何运行单个测试、单个包或聚焦的验证步骤
- 必须遵循的命令顺序，例如 `lint -> typecheck -> test`
- 单体仓库或多包边界、主要目录的归属，以及真正的应用/库入口点
- 框架或工具链的特殊之处：生成代码、迁移、代码生成、构建产物、特殊环境加载、开发服务器、基础设施部署流程
- 与默认规范不同的仓库特有风格或工作流约定
- 测试的特殊之处：fixture、集成测试前置条件、快照工作流、所需服务、不稳定或耗时的测试套件
- 现有说明文件中值得保留的重要约束

优质的 `AGENTS.md` 内容通常是阅读多个文件后才能推断出的宝贵经验。

## 问题

只有当仓库无法回答某个重要问题时，才向用户提问。最多使用一次 `question` 工具提出一小组简短问题。

适合询问的问题：
- 未记录的团队约定
- 分支 / PR / 发布要求
- 已知但未写明的设置或测试前置条件

不要询问仓库已经明确说明的内容。

## 编写规则

只包含信号密度高、仓库特有的指导，例如：
- 代理容易猜错的准确命令和快捷方式
- 无法从文件名明显看出的架构说明
- 与语言或框架默认规范不同的约定
- 设置要求、环境特殊之处和操作陷阱
- 对重要现有说明来源的引用

排除：
- 通用软件建议
- 冗长教程或详尽文件树
- 显而易见的语言约定
- 推测性说法或任何无法验证的内容
- 更适合存放在 `miaopan-code.json` 的 `instructions` 所引用的其他文件中的内容

如有疑问，就省略。

优先使用短小的章节和项目符号。如果仓库很简单，文件也应保持简单。如果仓库很大，只总结少数真正会改变代理工作方式的结构性事实。

如果 `${path}` 已经存在 `AGENTS.md`，请在原文件基础上改进，而不是盲目重写。保留经过验证的有用指导，删除空话或过时说法，并使其与当前代码库保持一致。
